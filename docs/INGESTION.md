# Ingestion спортивных данных

## Назначение

Ingestion-контур принимает уже нормализованное событие от адаптера поставщика и
атомарно обновляет канонический каталог bet.score. Конкретный внешний API не
входит в этот слой: его выбор зависит от покрытия, лицензии, SLA и бюджета.

## Идемпотентность

Единица доставки определяется сочетанием:

- ключ поставщика;
- внешний идентификатор события;
- версия данных поставщика.

Для исходного JSON вычисляется стабильный SHA-256 checksum с сортировкой ключей.
Повторная доставка той же версии и payload не создаёт новый snapshot. Изменение
payload при неизменной версии считается нарушением контракта и отклоняется.
Задержанная версия сохраняется для аудита, но не откатывает актуальное состояние
канонического матча. Размер одного исходного payload ограничен одним мегабайтом.

## Каноническое сопоставление

Внешние идентификаторы не становятся публичными UUID платформы. Таблицы
`provider_competition`, `provider_team` и `provider_event` связывают сущности
поставщика с каноническими сущностями. Уже существующая команда повторно
используется по сочетанию вида спорта и имени.

Операция защищена PostgreSQL advisory lock на ключ поставщика и выполняется в
одной транзакции: каталог и provenance не могут разойтись при частичном сбое.

## Provenance

`provider_event_snapshot` хранит:

- версию и время наблюдения поставщика;
- канонический UUID события;
- checksum;
- исходный JSON payload;
- время фактического ingestion.

Эти данные станут неизменяемым входом для объяснимого AI-анализа и аудита.

Публичный endpoint `/api/v1/events/{event_id}/provenance` раскрывает только
безопасные метаданные происхождения. Сырой payload и внешний ID поставщика
остаются внутри доверенного backend-контура.

## Transactional outbox

Каждый новый `provider_event_snapshot` и соответствующий `event_outbox` создаются
в одной PostgreSQL-транзакции. Повторная версия не создаёт дубликат сообщения:
`source_snapshot_id` имеет уникальное ограничение.

Отдельный процесс `bet-score-outbox` выбирает сообщения через
`FOR UPDATE SKIP LOCKED`, назначает ограниченный lease и публикует
`event.updated` в Redis. После ошибки сообщение освобождается с exponential
backoff до 300 секунд. Доставка имеет семантику at-least-once: crash после Redis
publish, но до PostgreSQL ACK может дать дубликат, безопасный для invalidation.
В `last_error_code` сохраняется только фиксированный код, без DSN и текста
исключения.

## Граница адаптера

Будущий адаптер поставщика отвечает за HTTP timeout, retry с jitter, rate limit,
валидацию ответа и преобразование в `ProviderEvent`. Секреты API не должны
попадать в snapshot, логи или доменную модель.
