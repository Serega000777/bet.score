# Журнал архитектурных решений

## ADR-001: FastAPI как backend MVP

- Статус: принято
- Решение: Python 3.13, FastAPI и SQLAlchemy.
- Причина: естественная интеграция с AI/data tooling и быстрый выпуск типизированного API.
- Последствие: фоновые задачи и web-клиенты используют отдельные технологические контуры.

## ADR-002: Модульный монолит

- Статус: принято
- Решение: единое deployable-приложение со строгими доменными границами.
- Причина: масштабирование команды и продукта пока не оправдывает стоимость микросервисов.
- Последствие: домены не импортируют инфраструктуру друг друга; интеграция идёт через application ports и события.

## ADR-003: REST + WebSocket

- Статус: принято
- Решение: REST для команд и восстановления состояния, WebSocket для LIVE.
- Причина: предсказуемость контрактов и поддержка real-time сценариев.

## ADR-004: pnpm workspace для клиентов

- Статус: принято
- Решение: web и Telegram Mini App управляются единым workspace.
- Причина: общие стандарты, быстрые установки и возможность выделить shared packages без копирования.

## ADR-005: провайдеры данных не выбраны

- Статус: отложено
- Решение: инфраструктурные адаптеры проектируются через порты, конкретный поставщик выбирается после исследования.
- Причина: в исходных документах недостаточно данных о лицензиях, покрытии и бюджете.
