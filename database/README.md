# База данных

PostgreSQL является источником истины. Миграции последовательно применяет команда `bet-score-migrate`. Она использует таблицу `schema_migration`, SHA-256 checksum и advisory lock, поэтому параллельные release job безопасны, а изменение уже применённого файла обнаруживается до запуска приложения.

Правила:

- UUID генерируются PostgreSQL;
- время хранится в `timestamptz` в UTC;
- внешние provider id не используются как первичные ключи;
- provider ID связаны с каноническими UUID отдельными mapping-таблицами;
- исходные версии событий сохраняются в `provider_event_snapshot` с checksum;
- миграции неизменяемы после применения в любом окружении;
- destructive migration требует двухфазного выпуска.

## Локальные данные

`migrations/900_seed.sql` добавляет один демонстрационный футбольный матч с нейтральными вымышленными командами. Seed безопасен для повторного запуска благодаря `ON CONFLICT`, но production-процесс должен исключить демонстрационную миграцию из утверждённого release manifest.
